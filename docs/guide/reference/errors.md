# Errors

The errors the Ayme runtime throws, what each means, and how a published tool reports a failure to an agent.

## Error classes

Ayme's own runtime failures are `AymeError` subclasses, exported from `@ayme-dev/ayme`. Each `name` is its class name, and `kind` tells them apart:

| Class                   | `kind`       | Meaning                                                           |
| ----------------------- | ------------ | ----------------------------------------------------------------- |
| `ToolInputError`        | `input`      | The caller's arguments are wrong.                                 |
| `RefResolutionError`    | `resolution` | A Structural Ref or Page Object instance does not match the page. |
| `RuntimeStateError`     | `runtime`    | Ayme is not set up for this call.                                 |
| `DecisionEndpointError` | `runtime`    | A call to the Decision Endpoint failed.                           |

A `RuntimeStateError` that callers branch on also has a `code` (`RuntimeStateErrorCode`), so they need not match its message. There are two: `active-owner`, for the owner conflict below, and `same-named-class`, for a Page Object refused because it reaches a different class with the same name as one already registered. A `DecisionEndpointError` always has a `code`, `not-mounted`, `rejected` or `malformed`, listed in the [Decision Endpoint reference](decision-endpoint.md#decisionendpoint).

`ayme.tools.run` throws them. Failures of the browser Page, such as a Playwright `TimeoutError` with its call log, pass through unchanged.

## How an agent sees a failure

A published tool never throws, because WebMCP drops the reason of a rejected call: native Chrome reports only a generic `UnknownError`. Every tool Ayme publishes, `snapshot` and `goal` included, resolves a failure as an MCP tool-failure result instead:

```json
{
  "content": [
    {
      "type": "text",
      "text": "RefResolutionError: Cannot click ref \"e12\": it is no longer on the page."
    }
  ],
  "isError": true
}
```

- `document.modelContext.executeTool()` resolves with this result's JSON, so a caller must read `isError`; the call does not reject.
- The text is the error's full message, prefixed with the error's name unless the name is plain `Error`. A browser action failure keeps playwright-lite's name and call log, such as `TimeoutError: locator.click: Timeout 1000ms exceeded.` followed by `Call log:`.
- Input that does not match the tool's input schema is refused first, before availability and before anything runs, with a sentence for each problem: `ToolInputError: Input property maxSteps must be at least 1. Input property extra is not supported.` A call with no input at all counts as `{}`.
- A call of an unavailable tool is refused the same way, before anything runs, with its reason: `RuntimeStateError: ProjectRow on ref "e11" is unavailable: Only admins can remove projects.` [Action availability](ayme.md#action-availability) shows the `ProjectRow` behind it.
- The result has no `structuredContent`.
- Inside the Goal Loop, a failed step does not end the call: the loop records its message in the Handover's history.
- A coding agent connected through [Ayme's MCP server](../guides/connect-an-agent.md) gets the same text in an MCP result with `isError: true`.

## Messages

Most messages say what is wrong. These are the ones whose cause is less obvious:

| Message                                                                                                                                                                          | Cause                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cannot <action> "<target>": <reason>.`, `Cannot <action> ref "<ref>": <reason>.` (`RefResolutionError`)                                                                         | The ref or selector matches no element or several, the ref's node was removed, or a rooted Page Object Tool's `ref` is not the root of an instance it covers.                                                                                                                                                                                                                                                                                                                                                                                           |
| `<class> at <path>: …`                                                                                                                                                           | An instance could not be observed as declared. The console message names the class and its path from the registered Page Object, such as `ProjectRow at ProjectsPage.projects[0]: its root matches 2 elements.` A registered Page Object is named by its class alone. It also reports a root or presence predicate that throws, a root or member that is not a browser locator, and a child that is not an object. A root matching no elements is ordinary absence and logs nothing.                                                                    |
| `<class>: its <member> matches <count> elements.`                                                                                                                                | A warning: a Locator declared [`@ayme.child`](../guides/ayme-page-objects.md#aymechild), which stands for one element, matches several. On a registered Page Object it reads `ProjectsPage: its newProjectButton matches 2 elements.` On a child it also names the path, as in `ProjectRow at ProjectsPage.projects[0]: its removeButton matches 2 elements.` It is logged to the console once, and again when the count changes or the warning comes back. The Page Object's tools stay published, but an action on that Locator fails in strict mode. |
| `There is no tool "<name>".` (`RuntimeStateError`)                                                                                                                               | No tool has that unprefixed name, such as a Page Object Tool whose class is not registered.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `<Tool> is unavailable: <reason>.`, `<Class> on ref "<ref>" is unavailable: <reason>.`, or either without `: <reason>` (`RuntimeStateError`)                                     | The tool cannot run now, and nothing ran. A call on one instance of a rooted class names the class and the ref, such as `ProjectRow on ref "e11" is unavailable: Only admins can remove projects.` (see [Action availability](ayme.md#action-availability)). [Unavailable reasons](#unavailable-reasons) lists each `<reason>`.                                                                                                                                                                                                                         |
| `The Ayme runtime already has an active owner.` (`RuntimeStateError`, `code: "active-owner"`)                                                                                    | A second session started in the same document, or in the same Node process. Start Ayme once, at the app's root or in the server's entry point.                                                                                                                                                                                                                                                                                                                                                                                                          |
| `<Class> has no compiler-derived Ayme metadata.` (`RuntimeStateError`)                                                                                                           | The build plugin did not compile the model: it is not marked `@ayme`, or the plugin does not transform its file.                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `The Page Object class "<class>" declares no root and …: <places>.` (`RuntimeStateError`)                                                                                        | See the [root-less class refusal rules](ayme.md#root-less-models).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `Cannot register the Page Object "<name>": …` (`RuntimeStateError`, `code: "same-named-class"`)                                                                                  | The Page Object, or a class it reaches, has the name of a different class a registered Page Object reaches, and the message names the files that declare both. Ayme tells classes apart by name, so it does not register the Page Object, and its tools are not listed until the Page Object it clashes with is unregistered. It is logged to the console, not thrown, so the component that registered it keeps rendering.                                                                                                                             |
| `Cannot publish the tool "<name>": another published tool already uses that name.` (`RuntimeStateError`)                                                                         | Two tools, such as a Custom Tool and a Page Object Tool, share a name. `ayme.tools.list()` is empty, so no tool is published, and `ayme.tools.run` throws it until the clash is fixed.                                                                                                                                                                                                                                                                                                                                                                  |
| `The <filter> function threw when the session started: …`, `The <filter> function did not return a Locator. …`, `The <filter> is not a valid CSS selector: …` (`ToolInputError`) | An element filter failed when the session started, and the session did not start. `<filter>` is `` `ignore` `` for the [`ignore`](ayme.md#createayme) option, or `` `filter` of the Custom Tool `<name>` `` for a Custom Tool's `filter`. For example: ``The `ignore` function did not return a Locator.`` A function threw, or returned something other than a Locator. A selector did not parse.                                                                                                                                                      |
| `createDecisionEndpoint must run on the server.` (`RuntimeStateError`)                                                                                                           | `createDecisionEndpoint` was called where `document` exists, which would put your key in the browser.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

### Unavailable reasons

| `<reason>`                                      | Tools                                                   | Cause                                                                                                                                                                                                           |
| ----------------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `a click would not reach it; e42 is in the way` | Page Object Tools; `click`, `hover`, `check`, `uncheck` | `e42` is the element a click would hit instead. See [Availability Reasons](ayme.md#availability-reasons).                                                                                                       |
| `it cannot take focus; e42 is in the way`       | `type`, `fill`, `select_option`                         | An open native modal or an `inert` ancestor, `e42`, keeps the target from taking focus.                                                                                                                         |
| `its Page Object is not on the page`            | Page Object Tools                                       | A root-less Page Object is absent, so `ayme.tools.list()` does not list its tools. A rooted call gets it when the instance's root left the page after the last observation.                                     |
| any other string                                | Page Object Tools                                       | The action's [availability predicate](ayme.md#action-availability) returned it.                                                                                                                                 |
| none                                            | Page Object Tools                                       | The availability predicate returned `false`.                                                                                                                                                                    |
| `its locator matches no element`                | Rooted Page Object Tools                                | The instance's root left the page just before the action ran. This one is thrown as `RefResolutionError`, such as `RefResolutionError: ProjectRow on ref "e11" is unavailable: its locator matches no element.` |

When nothing in the way has a ref, the reason ends before `; e42 is in the way`. A `fill_form` field refused this way gets the reason for its field type, in the result's `failed`. The fields filled before it stay filled.

Framework packages list their own errors in the Troubleshooting section of their page, such as [Vue](../frameworks/vue.md#troubleshooting). The build plugin's, including those for Page Object Child declarations, are in its [reference](build-plugin.md#errors), and `decisionEndpoint`'s in the [Decision Endpoint reference](decision-endpoint.md#decisionendpoint).
