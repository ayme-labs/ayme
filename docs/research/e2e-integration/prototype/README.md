# e2e integration prototype (research code, not a product package)

The code behind `../../e2e-integration.md` and the `results-*.md` notes beside it. It ran on one Mac against `apps/example-react`, with tester-army/e2e checked out at commit `5e032d95`. It is published for reference, not maintained, and nothing here is wired into this repo's build.

- `no-fork/`: the path the research recommends. A package on unmodified e2e: `src/ayme-tools.ts` (page object actions as e2e tools, root liveness), `src/store.ts` (the page object call store in `.e2e/ayme/`), `src/ayme-executor.ts` (store first, then the agent), `src/agent-solver.ts` (one agent session per test, the tool set defined once), `src/claude-code-driver.ts` (Claude Agent SDK) and `src/acp-driver.ts` (ACP: Claude, Cursor, Codex). `harness/` holds the e2e configs, the scripted model-free stand-in, and the tests (`tests/` single act, `tests-multi/` multi act, `tests-avail/` the liveness flip). Results: `../results-no-fork.md`, `../results-acp.md`, `../results-multi-act.md`.
- `patched-e2e/`: the first round, on a patched e2e (`fork-patch/`). Executors for the scripted stand-in and Claude Code, `pom-from-e2e.ts` (the deterministic plan and the repair patch from cache entries), `pom-agent.mjs` (the coding agent that writes a page object from the plan), and `samples/` (cache entries, the plan, a repair proposal and patch, the generated page object). Results: `../results-claude-code.md`, `../results-pom-from-cache.md`.
- `fork-patch/e2e-fork.patch`: the patch to tester-army/e2e's `packages/` (replayable tool calls, keep-and-propose repairs, fail-fast replay, `StepExecutor.replayTools`, the container-key fix). tester-army/e2e is Apache-2.0; the patch is a derivative of its source at `5e032d95` and carries that license.
- `example-react/`: the experiment's changes to `apps/example-react`: the Projects screen (`main.tsx.diff`) and `ProjectsPage`/`CounterPage` with a `root` per the page-object-design reference.

Credentials were passed at run time only and appear nowhere here. The Codex isolation list reads the user's own MCP server and plugin names from `SPIKE_CODEX_MCP_SERVERS` and `SPIKE_CODEX_PLUGINS`.
