# Page Objects declare their own root and presence

ADR-0009 made a top-level Page Object present while it is registered and ruled that activation is not inferred from URLs; ADR-0020 made a rooted one present while a member named `root` resolves to one rendered element, and ruled out consumer configuration. Both are conventions of Ayme's own, and a consumer who does not follow them has no way to say when a Page Object is on the page: registering every model at app setup lists every page's tools on every page, and a model whose anchor is not called `root` fails quietly. We let the model say both. The class decorator takes two inherited options, `root`, which names the element that anchors the Page Object, and `present`, which says when it is on the page. Each is a predicate that gets the live Page Object, runs read-only with the observation and never with a call, as an action's availability predicate does (ADR-0035), and is kept at runtime beside the class and read along the class chain, nearest declaring class wins, so a consumer writes each once on a base class of their own. The defaults are today's behaviour: a model with a root is present while the root resolves to one rendered element, a top-level model without one while it is registered, and a single child with neither option while the Page Object it is reached through is; with both options, the root must resolve and the predicate narrows. A predicate that withdraws a Page Object stops the walk at it: its root is not read and its members are not walked, so a child of it is absent with it; a root that is not on the page does not, since ADR-0020 keeps a present child inside a Page Object that is not. A root predicate that throws is reported as a presence predicate that throws is. The predicate is evaluated before the model's members are read, so an absent model costs one call per observation. A predicate that throws makes the Page Object absent with the error reported; presence carries no reason, since an absent Page Object's tools are listed nowhere a reason could show. The observation is also scheduled on same-document navigation, so a page present by its URL follows the browser's history. The member named `root` stops anchoring a model on its own; only the option does, and a locator member that resolves to the root's element is left out of the listed children.

We considered a class-level availability predicate instead, rejected because a page the browser is not on is ADR-0020's collapsed sidebar, not its modal-blocked page: it leaves the page state rather than staying listed with a reason. We considered a shipped route or URL helper, rejected because the consumer's router already knows the routes; and a list of Page Objects on the session options, rejected because no new registration API is needed once a page can state its own presence. The cost is that the runtime refuses a collection item without a root and the compiler does not check it, and that Ayme's conventions become recommendations in the docs rather than assumptions in the runtime. This decision amends ADR-0020, whose rule against consumer configuration now holds for availability measurement only, and supersedes the sentence of ADR-0009 that Page Object activation is not inferred from URLs. ADR-0009's observation lifecycle and ADR-0035's precedence stand.
