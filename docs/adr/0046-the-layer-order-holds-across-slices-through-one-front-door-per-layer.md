# The layer order holds across slices, through one front door per layer

The ayme package is cut into slices with `domain`, `application` and `infrastructure` layers, and lint kept the layer order only inside a slice. Another slice was reached through a single front door outside its layers, so lint could not tell which layer a name came from: an application module could act through another slice's infrastructure, and a domain rule could call another slice's application, and lint flagged neither. The package's rule that domain and application reach the browser only through what they are handed was therefore checked one slice at a time. We let the layer order hold across slices as it holds inside one: domain uses domain, application uses application and domain, and infrastructure uses any layer. A layered slice has no front door of its own. Each of its layers that other code uses has one, inside that layer's folder, so lint judges an import through it by the layer it sits in, for every kind of import lint already reads, and a door cannot pass on a name from a layer its own layer may not use. Unlayered slices keep their single front door, and the slice order is unchanged.

We considered following each name through the slice's front door to the module that declares it, rejected because it needs a rule of our own that repeats what lint already reads for every kind of import, and it leaves the layer of a dependency hidden where it is imported. We considered letting each front door state which of its names are infrastructure, rejected because the statement needs its own check and can still be wrong. The imports that break the order today are listed in one named allowlist beside the rule, each with the issue that removes it, and a test fails when an entry no longer matches an import, so an entry leaves the list when its issue is done. Unlike the direct page access ADR-0045 leaves unenforced, which no planned work removes, every exception here has an issue that does. We considered ESLint's bulk suppressions instead, rejected because they count violations per file, so one import can replace another unnoticed, and they cannot name the issue that removes them. The cost is that a layered slice has up to three front doors instead of one, every import from a layered slice names the layer it uses, and code that needs an exception before its issue is done adds an entry naming that issue. The mcp package and the Inspector keep a single front door per slice.
