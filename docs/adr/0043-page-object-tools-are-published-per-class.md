# Page Object Tools are published per class, and a root's ref picks the instance

A Page Object Tool was named by the member path from the registered Page Object that reached it, while the page state and an action's return type named the class: an agent read that a call showed a `ResponseFilterPopover` and had to find the tool under a path prefix, and a class reached from several places, or from several registered Page Objects, was published once per path, with collections given a tool shape of their own. We publish one Page Object Tool per Page Object Action of a class, named after the class, and drop path names. Class names are already unique across everything registered, so they are safe as the tool namespace. A tool of a class with a Page Object Root takes the Structural Ref of the instance's root, which picks the instance wherever it was reached, in a collection, at any depth of a recursive tree or as a single child, and the tool is listed while any instance is on the page, its availability judged per instance at the call. A tool of a class without a root takes no ref, so a root-less class reached from more than one place, a child of a collection item included, is refused, by the build where it can prove it and at registration otherwise: nothing could pick between its instances. Two instances of one class on the same root element are one instance, since the ref cannot tell them apart and a model whose members hang off its root resolves them to the same elements. The page state labels each Page Object Root with its class, so the names an agent reads are the names it calls. We considered keeping path names, rejected because they publish a class once per path and leave the agent two vocabularies; class names with the path as an argument, rejected because the agent would have to know the model's tree to call a tool, while the ref already addresses the element it sees; and leaving the ref out where a class has one instance, deferred, since making the ref optional later breaks no caller. The cost is that every call to a rooted Page Object carries a ref even when only one instance exists, that a root-less class shared by two parents needs a root before it registers, and that path names go without aliases, so existing callers, docs and skills move with the change.
