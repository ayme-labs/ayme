# Page Object Children are declared

ADR-0007 derives a Page Object Model's development-time contract from TypeScript visibility and static types, and until now that included its children: the build counted every public field or getter typed as a locator or as a Page Object, and every public method without parameters that returns Page Objects, as a Page Object Child. A member is now a child only when its model declares it, with one member decorator for a single child and another for a Child Collection, either of which can carry a description. A member that is not declared is not a child whatever its type, so a public locator can serve tests without entering the model. A declaration on a member that holds neither a locator nor a Page Object, or on a shape the guide does not list, fails the build, as does one whose type the build cannot resolve.

We declare children because a locator's type cannot say whether it stands for one element or for many, and only the author knows. The declaration says so, which lets Ayme warn when a single child matches several elements and name each element of a collection by its index. It also tells a helper locator from a part of the page, which inference could not, and it replaces the guess that a parameterless method returning Page Objects is a collection. Page Object children are declared too, though their type already names their model, so that authors follow one rule, every child can carry a description, and the model is exactly what was declared, as Page Object Tools come only from marked actions (ADR-0007). The build's type analysis stays: a declared member's type still names its model and must agree with its declaration. The change buys explicitness, not a smaller compiler.

We considered declaring only locator children and recognising Page Object children by their type, rejected because it keeps two rules and leaves undescribed children in the model. We considered keeping inference and using decorators only to add descriptions, rejected because it keeps accidental children and leaves a locator's cardinality unknown. We considered one decorator with the cardinality read from the type, rejected because a locator's type carries none. The cost is that every existing model must declare its children, with no fallback while Ayme is pre-release, and that a declaration forgotten on a Page Object member silently removes that child from the model and, unless its model is reached another way, its tools from publication. A declared child that resolves to its Page Object's root is the root, not a child, as ADR-0042 rules. Structural Page State still marks only Page Object Roots; marking children is a separate decision.
